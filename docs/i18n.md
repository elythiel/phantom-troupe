# Languages

The repository is written in English. The troupe speaks whatever `owner.language` says. Those
are two different things, and they are translated by two different means.

## Two kinds of text

**Text the model writes** — ticket descriptions, refinement notes, reviews, commit messages,
everything a member produces. There is nothing to translate here. Each agent carries one
instruction: write every user-facing output in the configured language. Set `owner.language`
to `fr` and the troupe writes French, with English agent instructions underneath.

**Text the plugin writes** — the strip above the prompt, the `/troupe-board` table, the error
messages the mod prints. These are hardcoded strings in JavaScript, and those are what the
locale files are for.

That split is deliberate. Putting a translation layer over prompts would mean maintaining seven
agent briefs per language; asking the model to answer in a given language costs one line and
works for every language it knows.

## Locale files

One JSON file per language in `locales/`, named by its BCP 47 tag: `en.json`, `fr.json`,
`pt-BR.json`. `en.json` is the source of truth and holds every key.

Lookup goes, for `owner.language`:

1. the exact tag — `pt-BR` → `locales/pt-BR.json`;
2. the base language — `pt-BR` → `locales/pt.json`;
3. `en.json`.

A key missing from a locale falls back to `en.json` on its own, so a partial translation is
useful from its first key. A locale file is never required to be complete.

## Placeholders

A value may carry `{name}` placeholders, substituted at display time:

```json
"stepOf": "step {current}/{total}"
```

Keep every placeholder of the English string in your translation, in whatever order the language
needs. A placeholder that does not exist in `en.json` is printed as-is, which is how you notice
it.

## Adding a language

1. Copy `locales/en.json` to `locales/<tag>.json`.
2. Set `$meta.language` and `$meta.name`.
3. Translate the values, never the keys.
4. Set `owner.language` to that tag in your configuration.

`$meta` is not displayed; it exists so a file can be identified on its own.

## What is deliberately not translated

- **Step identifiers** (`ticket`, `refine`, `design`, `dev`, `review`, `test`, `ship`) and
  **state identifiers** (`todo`, `doing`, `review`, `done`). They are stored in the archive and
  compared in code, so they stay English everywhere. Only their labels are translated.
- **Member names.** Chrollo is Chrollo.
- **The archive's file and directory names.** They are an on-disk format, not a text.
